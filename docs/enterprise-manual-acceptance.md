# 企業展示版人工驗收

這份清單供換機後手動操作。自動測試通過不代表這些人工驗收已完成，也不代表真實公司可以直接上線使用。

## 前置條件

依根目錄 README 設定離線模式、匯入虛構制度，並以互動命令建立 employee、manager、hr 三個個別帳號。需要測試維護功能的人資帳號另外授予 `knowledge:manage`。密碼自行設定，不加入 Git。

示範資料全部是虛構流程，沒有個人出勤、剩餘假別或真實核准交易。離線模式只提供來源摘錄；雲端外送預設不允許。本次驗收不需要 API key。

## 操作清單

| 情境 | 操作 | 應觀察的結果 | 人工結果 |
|---|---|---|---|
| 登入前 | 開啟企業入口 | 看見登入與展示標示，沒有制度內文或來源清單 | 未執行 |
| 員工查流程 | employee 查詢「補打卡要填寫哪些說明？」 | 可對照一般制度；看不到主管指引、人資 SOP 或草稿 | 未執行 |
| 主管查指引 | manager 查詢「主管如何確認交接安排？」 | 可讀主管指引；人資 SOP 與草稿不可讀 | 未執行 |
| 人資查 SOP | hr 查詢「制度疑義如何確認版本與生效日？」 | 可讀明確授權給人資的 SOP | 未執行 |
| 維護能力 | 比較一般 hr 與有 `knowledge:manage` 的 hr | 只有指定維護者可執行管理功能 | 未執行 |
| 新舊版 | 查詢日分別選 2026-10-31、2026-11-01，問請假申請流程 | 前者引用 v1；後者引用 v2，能確認代理交接要求與版本日期 | 未執行 |
| 證據不足 | 問「火星火山地質」 | 回報沒有相關證據，不編造制度 | 未執行 |
| 範圍外個資 | 問「我剩幾天特休？」 | 不產生個人餘額或聲稱已查詢人事系統 | 未執行 |
| 來源核對 | 展開引用並對照原文 | 顯示虛構標示、來源版本、適用日期及原文；內部識別碼不當成公開網址 | 未執行 |
| 登出換帳號 | 查詢後登出，換另一帳號登入 | 前一人的答案與紀錄不殘留 | 未執行 |
| 本人紀錄 | 兩帳號分別查詢並查看紀錄 | 各自只能查看與回饋自己的紀錄 | 未執行 |
| 停用／改角色 | 本機管理命令停用或改角色後，原登入頁重新操作 | 舊登入立即失效，不再顯示原答案 | 未執行 |
| 草稿發布 | 維護者預覽並匯入新的虛構 JSONL，再另行發布 | 匯入先成為草稿；正式發布且已生效後才能查詢 | 未執行 |
| 撤回 | 維護者撤回已發布版本，再重新顯示原答案 | 撤回內容不再提供；不自動恢復已被新版取代的舊版 | 未執行 |

管理流程請使用新文件 ID 或新版本測試。同版本內容不可覆寫；已發布或已撤回版本不可降回草稿。需要再次提供撤回版本時，必須明確恢復為 published。

## 真實模型與企業價值仍待驗證

在另行確認付費測試預算及資料外送許可後，才測試真實模型。逐題核對答案正確性、引用是否支持每個主張、條件與例外是否完整、缺條件時是否追問、衝突時是否保留差異。引用 ID 有效不能代替語意正確。

另請代表性員工、主管、人資各完成一項工作，記錄成功／失敗、耗時與不理解的地方。先記錄人工查找基準，再比較使用助理後的結果；沒有這些紀錄時，不宣稱節省多少時間或提高多少效率。

開發與回歸題組由本次實作流程編寫，只能視為工程回歸證據，不能當作獨立人類保留集。
