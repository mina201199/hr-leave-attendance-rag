# 精簡企業版設計（2026-10-22）

使用者已確認：單一公司、請假與出勤制度、employee／manager／hr，先採用明確標示虛構的制度開發及測試。

## 範圍

沿用 Python、Streamlit、SQLite 與既有 `labor_rag` 核心。原版 `app.py` 保留；新增 `enterprise_app.py` 作企業入口，避免讓原版測試與資料庫一起變更。一般使用者能查制度與本人紀錄；具 `knowledge:manage` 能力的人資可管理文件。沒有預設帳密，透過本機互動命令建立帳號。模型選型不變，本次驗證只執行離線與 mock。

公司制度以虛構流程為主，不新增或編造法定假別日數、工資計算與法律結論。制度包含一般申請、補打卡、主管審核、人資特殊處理及一份新舊版流程。每段標示虛構且附受控來源識別碼。

## 架構與責任

1. 既有 DocumentChunk 增加企業中繼資料，原版公開資料可繼續載入；內部資料必須明確 ACL、維護者、生效日及草稿／發布狀態。
2. KnowledgeStore 保留版本 payload 不可變；文件發布狀態獨立管理。草稿不遮蔽現行發布版，也不得直接撤回；撤回已生效發布新版不得回復舊版；遷移保留舊資料。
3. AuthStore 使用個別帳號與密碼雜湊，資料庫只存 session token 雜湊；每次請求重讀帳號與權限。角色變更、停用、改密碼皆撤銷舊 session。
4. EnterpriseService 的外部操作接收 session token，由 AuthStore 取得 Principal。使用者不能直接傳入角色。服務內集中使用 policy 篩選資料。
5. 查詢先依角色、日期、已發布狀態與來源 ACL 篩選，再用原有檢索與上下文。雲端處理另外檢查外送許可。生成前後再次查核授權及來源一致性。
6. 內部引用只能透過受控服務按 token、來源 ID 與日期讀取；猜 ID 與未知來源回傳同一錯誤。不把內部來源偽裝成可公開開啟的 URL。
7. 企業查詢紀錄只存擁有者、問題雜湊、來源識別碼、版本、模式與狀態，不保留問答原文。紀錄與回饋僅本人可用；人資沒有全庫紀錄權限。
8. Streamlit 只保存 session token 與目前答案，不快取含身分的 runtime。登出清除頁面結果；每次重繪重新檢查舊答案的授權與版本。

## 驗收

- 原版測試繼續通過，原資料庫不遷移、不重建、不寫入企業資料。
- 三角色各自看到允許的制度，員工看不到主管／人資專用內容。
- 草稿、撤回、未生效、過期、錯誤 ACL、未知引用、停用帳號、失效 session、跨帳號紀錄均不可繞過授權。
- 缺乏條件或來源不能編造流程；保留完整原文對照，官方與虛構內規分開。
- mock 生成器輸入不得含未授權來源；雲端未允許來源不得被 embedding 或生成。
- 自動測試與開發評估不等於真實 LLM 品質、人類使用者驗收或獨立研究保留集。

## 本次實作決定

- 保留 `app.py` 原版，企業入口另建 `enterprise_app.py`，比直接改寫原版更容易維持基準與換機驗證。
- 官方快照及歷史公開報告沿用；不呼叫付費 API、不提高預算。
- 測試用密碼以隨機值在執行時產生，不在程式、範例與測試檔放固定可登入密碼。
- 所有新制度只是虛構展示內容；不接個人資料或真實核准交易。
